# 0.1.4 release validation

## Scope

This release fixes the inline fork menu's default state, archived-only placement, long-menu fold behavior, workspace-expansion animation origin, and the completion-reminder position. It also clarifies that a new fork's composer stays empty.

Release preparation changes version identifiers (0.1.3 → 0.1.4), internal semver ranges, the workspace lockfile, release/install documentation, and adds the 0.1.4 release notes and artifact manifest. Feature logic was accepted in the tree-test profile before this packaging step.

Release preparation is `triage_skip` under the project's version/documentation/generated-artifact exemption. The feature work was reviewed same-family; cross-family review was unavailable. This record does not claim cross-family approval.

## Mechanical checks

- Host and client TypeScript checks passed.
- Vitest: 17 files, 226 tests passed.
- Three implementation builds and the four-package artifact/dry-run checks passed (`verify-bundle --pack`).
- All four manifests, internal dependency ranges, the client `SESSION_TREE_VERSION`, README/INSTALL references, and the CHANGELOG heading are 0.1.4.
- The four tarballs were packed from this build; `docs/releases/0.1.4-manifest.json` and `0.1.4-SHA256SUMS` record their sizes, file counts, SHA256 and SHA512 integrity.

## Installation and runtime boundary

The same build (before the version-only bump) was installed into the `tree-test` profile and exercised for the fork-menu, workspace-animation and completion-dot changes. The desktop profile was updated to the same client build for final acceptance; desktop acceptance requires a full application restart and is owned by the user.

No fresh isolated four-tarball fixture install was repeated for this release. The tarballs were produced by the verified build and their contents were checked by `verify-bundle --pack`; this record does not claim an independent clean-profile installation.

## Distribution

The accompanying JSON manifest and SHA256SUMS identify the four final tarballs. Source/tag pushes, GitHub release assets, and npm registry publication are separate actions. This release operation packages locally; it does not push, tag, publish to npm, or update the plugin marketplace.
